# 何時該（不該）用 Agent

## 判斷順序
1. 先問：單次 LLM 呼叫 + 檢索 + 範例夠不夠？很多情況夠了 [S1]。
2. 流程固定、任務定義清楚 → workflow [S1]。
3. 開放式問題，無法預測步驟數、不能硬編碼路徑，且你對模型決策有一定信任 → agent [S1]。
4. 先從單一 agent 開始，再視需要演進到多 agent [S4]（二手摘要）。

## 適合 agent 的條件（Anthropic 附錄）
- 同時需要對話與行動、成功標準清楚、可形成回饋迴圈、有有意義的人類監督 [S1]。
- 客服：流程是對話，需存取外部資訊與動作（如退款、更新工單），且成功可用「問題解決」衡量 [S1]。
- Coding：解法可用自動測試驗證、能用測試結果迭代、問題空間結構清楚、品質可客觀衡量 [S1]。

## 三原則
簡單、透明（顯示規劃步驟）、精心設計 ACI [S1]。
